Program Management With AI Agents

How I use Claude Code to take repetitive work off my plate, and my team's

I'm a program manager, not a software engineer. But a lot of program management is repetitive: pulling data, checking dates, writing the same kind of update every week. Over the past year I've used Claude Code, an AI coding assistant, to automate that work. I decide what to automate, define the rules and review every result. The AI writes most of the code.

What I've automated

Release sales enablement

Before each release, sellers need to know what's new and how to sell it. Building that content took 5 people about a week. Now a Claude Code skill scans Jira tickets, GitHub pull requests, and the code base into a training deck with narration in under an hour.

Security SLA tracking

Vulnerability tickets need due dates based on their priority. One skill fills in missing due dates. Another finds overdue tickets and leaves a comment tagging the right technical lead.

Sprint quality reports

A skill reads a sprint's tickets and comments, counts the defects found in testing and produces a spreadsheet for the retrospective.

Backlog and board upkeep

Skills rank tickets from a shared spreadsheet and move tickets to the right board columns based on their parent epic.

Together, my 7 automations save about 140 hours a month.

What I've learned

  1. Start with the task everyone dreads. If people do it every week and complain about it, it's a good candidate.
  2. Write the rules down first. If I can't explain the steps to a new hire, I can't explain them to AI tooling.
  3. Test on real data. A skill that looks right on a sample often breaks on real tickets, so I test against live data before anyone relies on it.
  4. A human approves anything impacting production. The AI drafts, and a person reviews before anything is sent or changed at scale.
  5. Keep credentials safe. Passwords and access tokens go in a secure store, never in scripts or chat.
  6. Share what works. Each automation is a saved skill that teammates can run with one command.

Why it matters for program managers

Program managers who can define a process clearly can now automate it, without waiting for an engineering team. The skill that matters most isn't coding. It's knowing exactly what good output looks like and checking it.
